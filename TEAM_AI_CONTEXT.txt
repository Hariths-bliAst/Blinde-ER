1. PROJECT OVERVIEW & COMPETITIVE EDGE
--------------------------------------------------------------------------------
- Application Name: Blind-ER
- Target Audience: Visually impaired, legally blind, and partially sighted users.
- Core Problem: Standard OCR-to-speech tools read scanned text robotically and
  literally—reading out broken hyphenations, stray page numbers, and awkward
  word-for-word translations that strip away emotional tone, genre nuance, and
  logical narrative flow. Furthermore, most scanning apps rely on small visual
  buttons that are inaccessible to blind users.
- Our Innovation (The 3-Step AI Pipeline):
  1. Custom CRNN (Convolutional Recurrent Neural Network): Trained by Project
     Lead Hariths to accurately extract raw text from physical book pages.
  2. Context-Aware LLM Engine (Gemini API): Acts as a professional audiobook
     narrator and literary translator. It cleans flawed OCR output, fixes
     structural breaks, preserves genre/emotional tone, and translates smoothly
     into the user's target language.
  3. Native TTS & Screen Reader Integration: Routes the expressive text directly
     into native mobile Text-to-Speech (TTS) with full Android TalkBack and iOS
     VoiceOver integration, controlled via a full-screen, voice-first gesture
     interface (no tiny buttons required).

--------------------------------------------------------------------------------
2. TECHNICAL STACK & STRICT ARCHITECTURAL RULES
--------------------------------------------------------------------------------
- Frontend: React Native (Expo bare-compatible workflow with `expo-camera`,
  `expo-speech`, `expo-haptics`, and native `AccessibilityInfo`).
- Backend/Middleware: Python (FastAPI) handling CRNN routing (`/api/extract-text`)
  and Gemini LLM orchestration (`/api/contextualize` & `/api/scan-book-page`).
- CRITICAL SECURITY RULE:
  * NEVER hardcode API keys, LLM tokens, or private URLs in any code or doc file.
  * All secrets live exclusively in `.env` files, which are blocked from Git via
    `.gitignore`. Use `.env.example` only for placeholder variable names.
- STRICT SEPARATION OF CONCERNS (LOGIC vs. UI/STYLING):
  * Core logic, camera capture, state machines, and API calls live ONLY in:
    - `frontend/src/logic/`
    - `frontend/src/api/`
    - `backend/`
  * UI layouts, visual themes, and stylesheets live ONLY in:
    - `frontend/src/ui/` (Specifically `theme/`, `screens/`, and `components/`)

Design & Accessibility Standards for Matthew:
1. High-Contrast Palettes (WCAG AAA - 7:1+ contrast ratio):
   - Pure black backgrounds (`#000000` or `#0A0A0E`) paired with hyper-legible
     high-luminance accents: Safety Yellow (`#FFD600`), High-Vis Cyan (`#00E5FF`),
     Crisp White (`#FFFFFF`), and Accessible Emerald (`#00E676`).

   - Never use small icons or cramped buttons. Every interactive zone must span
     full width or full screen (minimum 72dp height for secondary controls).

   - Always include `accessible={true}`, `accessibilityRole`, `accessibilityLabel`,
     `accessibilityHint`, `accessibilityState`, and `accessibilityLiveRegion="polite"`
     (or `"assertive"` for errors/state changes).
